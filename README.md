# VerbaTrace Frontend

React/TypeScript-интерфейс VerbaTrace. Приложение работает поверх
[backend API](https://github.com/SHILOP0P/VerbaTrace-backend) и покрывает звонки, транскрипцию и
анализ, инструкции и их версии, Human QA, действия, компании/отделы, тарифы и
credits, developer integrations, администрирование и профиль. Рабочее окно
ассистента объединяет поиск по звонкам и отдельный режим исследования.

## Стек

- React 19
- TypeScript 5.9
- Vite 7
- MobX
- Lucide React
- Безопасный Markdown-предпросмотр инструкций, подготовленный backend

## Локальный запуск

Используется локальный HTTPS. Сначала подготовьте сертификат и runtime-роль по локальному руководству backend `docs/runbooks/local-security/README.md`: `Monolit/scripts/setup-local-security.ps1 -TrustCertificate`, затем `task up`. Секреты и `.local-security` не коммитятся. Не отключайте проверку сертификатов.

Изменяющие запросы проходят Origin/CSRF, загруженные файлы — асинхронную серверную проверку с восстановлением статуса при навигации. Оригиналы Office/PDF в браузере не разбираются; HTML в Markdown отключён, внешние изображения не загружаются. Эти правила сохраняются при добавлении новых компонентов и API-клиентов.

После простоя клиент восстанавливает доступ через действующую refresh-сессию. Диалог «Сессия завершена» требует подтверждённого отказа авторизации; временная ошибка сети/сервера или CSRF не считается завершением сессии. При явном CSRF-отказе до обработки действия клиент получает актуальный токен и допускает один повтор запроса с повторно используемым телом; принятые запросы и сетевые ошибки автоматически не переотправляются.

В черновике инструкции кнопка «Заменить файл» открывает проводник и принимает перетаскивание одного файла, сохраняя предпросмотр на месте во время выбора и проверки. PDF отображается как извлечённый Unicode-текст без Markdown-разметки; Excel — как таблицы листов. Оригинальная вёрстка PDF, оформление ячеек Excel и OCR сканов в текстовый предпросмотр не входят.

Во время подготовки критериев анимация располагается по центру колонки без внутренней прокрутки; готовый длинный список прокручивается. Статусы проверок загруженных файлов доступны по значку документа с галочкой в верхней панели рядом с уведомлениями. Список закрывается повторным нажатием, крестиком, Escape или нажатием вне панели.

Проверки: `npm.cmd run build`, `npm.cmd run test:server`, `npm.cmd run security:dependencies`. CI выполняет их для новых изменений. Локальные инструкции для агента — `AGENTS.md` (по политике репозитория остаются вне Git).

Backend должен отвечать на `http://127.0.0.1:8080`. Сервер собранного сайта
проксирует туда `/api` и `/health`. Для другого адреса backend задайте
`API_TARGET` перед запуском сервера.

HTTP-клиент по умолчанию использует текущий origin. `VITE_API_BASE_URL` задаёт
другой адрес API во время сборки; `API_TARGET` меняет адрес серверного прокси
во время запуска и не требует пересборки.

Выполните из корня репозитория:

```powershell
npm.cmd ci
npm.cmd run start
```

Единый адрес сайта и API — `https://127.0.0.1:5173`. Команда сначала проверяет
TypeScript и собирает сайт, затем запускает `scripts/serve.mjs`, который отдаёт
только `dist`. HMR, dev-сервер и выдача исходников отключены. Прежние команды
`npm.cmd run dev` и `npm.cmd run demo` запускают тот же собранный сайт. Если
сборка уже готова, `npm.cmd run serve` запускает её без повторной сборки.
Порт закреплён: если 5173 занят, запуск остановится до сборки с пояснением.
Сервер работает в вашей консоли: оставьте её открытой, а для остановки нажмите
`Ctrl+C`. Перед повторным запуском остановите предыдущий сервер.

## Показ сайта через туннель

Текущий профиль рассчитан только на localhost. Старый запуск через туннель несовместим с точными проверками Host/Origin. Для внешнего показа требуется отдельный согласованный профиль; не отключайте защиту localhost ради туннеля.

Страницы приложения и 3D-иллюстрации загружаются отдельными JS-чанками.
Сборка создаёт также gzip/Brotli-варианты; сервер выбирает их по
`Accept-Encoding`. Чанки с хешем в имени кешируются как immutable, HTML и
модели без хеша продолжают проходить проверку актуальности. Запросы к исходникам,
dev-runtime и отсутствующим чанкам возвращают 404. Сервер передаёт запросы к
backend потоком, сохраняет cookies и Range для медиазаписей. Для постоянного
размещения можно использовать этот сервер за HTTPS-прокси или статический
хостинг каталога `dist` с отдельным прокси для `/api`.

## Поиск и исследование звонков

Окно «Работа со звонками» доступно после проверки backend capabilities и
поддерживает личный и разрешённые корпоративные контексты. Список чатов,
переименование, редактирование вопроса и черновик работают через API.
Контекст вопроса включает выбранные звонки, папки и период; звонки и папки
можно добавить через `+` или `@`.

«Поиск» получает релевантные фрагменты, «Исследование» запускает отдельный
асинхронный процесс с уточнениями, прогрессом, паузой, продолжением и отменой.
Ответ отображается одним сообщением с отступами между разделами. Правая панель
показывает источники, итоги и диаграммы; отчёт можно скачать в доступном формате.
Наличие интерфейса не означает завершённую приёмку исследования на реальном
провайдере: функциональность ассистента на бэкенде остаётся в разработке.

Ширина боковых панелей, выбранный формат экспорта и свёрнутое состояние блока
результатов сохраняются в `localStorage`. Закрытие, повторное открытие,
разворачивание окна и обновление страницы не сбрасывают состояние этого блока.
Переключатели и сворачивание анимированы с учётом `prefers-reduced-motion`.
У окна отдельные стили `src/styles/assistant.css` для светлой и тёмной тем.

## Bitrix24

Экран управления connection включает server-side OAuth, проверку capabilities,
pause/resume/reconnect, сопоставление пользователей и отделов, preview и запуск
backfill, историю импортов и аудит. Руководитель компании может быть сопоставлен
без отдела; для остальных сотрудников нужен активный отдел.

Диапазон backfill сохраняется в `localStorage` отдельно для UUID подключения.
Состояние `degraded` отображает доступные и недоступные возможности независимо:
например, импорт звонков остаётся доступным при подтверждённом чтении статистики,
даже если OAuth-пользователь пока не может создавать задачи.

Действие отправляется в Bitrix24 только через отдельный preview/request и решение
другого manager/department leader. Неоднозначный ответ и внешние изменения задачи
показываются как состояние, требующее ручного решения.

`Проверено на портале` нельзя считать успешным только по OAuth и read-only health
check. Нужна отдельная приёмка настоящего звонка, доступной записи, импорта и
task-flow. Аренда номера и телефонный трафик Bitrix24 могут быть платными.

## Темы и layout

Основные рабочие экраны используют общие app tokens и полностью поддерживают
светлую и тёмную темы. Для длинных панелей используется общий
`CustomScrollbar`; page layouts сохраняют одинаковые отступы относительно header
и sidebar. При добавлении элементов нельзя вводить отдельную визуальную модель,
если в проекте уже есть эквивалентный control.

Основа оформления — `src/styles/refresh.css`; окно ассистента дополнительно
использует `src/styles/assistant.css`. Шкала
поверхностей одна на обе темы: холст `--vt-canvas` → панель `--vt-s1` →
вложенный блок `--vt-s2` (заливка без второй рамки) → подсказка `--vt-s3`;
текст `--vt-text`/`-2`/`-3`, линии `--vt-line`, тона `--vt-good`/`-warn`/`-bad`/`-info`
и их `-soft`, длительности `--vt-dur-fast`/`--vt-dur`/`--vt-dur-slow`. Старые
`--app-*` указывают на эту шкалу. Оранжевый акцент — только действия, активная
навигация и фокус; данные показываются нейтральным цветом и тонами статуса.
Шрифт Inter подключён из пакета `@fontsource-variable/inter`, без внешнего CDN.
Оценка 0–100 везде показывается одним компонентом `ScoreGauge`, текст анализа
перед показом проходит через `stripAnalysisRefs`: служебные номера карточек,
требований и сегментов пользователю не показываются.
У метрики свой цвет серии (`--vt-chart-blue`/`-violet`/`-green`/`-teal`), общий
для её иконки и линии графика. Иконка, называющая страницу или блок, стоит на
нейтральной плитке `.page-emblem`; сегментированные переключатели (`.segmented`)
и фильтр спикеров — с нейтральным ползунком. В окне ассистента активный режим
выделяется оранжевым ползунком. Тона в светлой теме
подобраны так, чтобы текст держал 4.5:1 на своей мягкой подложке.

## Публичный лендинг

Основной лендинг открывается на `/`. Дополнительные страницы: `/product`,
`/pricing`, `/integrations`. Вход и регистрация доступны через `/login` и
`/register`; письмо восстановления открывает `/reset-password?token=…`.
После входа сохраняется запрошенный адрес `/app/…`.

Публичные страницы используют `src/public-entry.ts` и `src/features/landing/main.tsx`; кабинет —
`src/main.tsx` и отдельный документ `app.html`. Сервер выбирает документ по
адресу. Страницы кабинета не входят в пакет лендинга. Формы авторизации вынесены
в `src/features/auth/AuthDialog.tsx` и используют действующий API.

3D-иллюстрации создаются в React Three Fiber из геометрии, без моделей офиса,
текстур и iframe. До готовности WebGL отображается прозрачная SVG-версия.
Предпочтение темы общее с кабинетом. Общая кнопка `ThemeToggle` использует контурные
иконки: текущая уходит влево, следующая появляется справа; сохраняется волновая
смена темы и системный `prefers-reduced-motion`.

Старые адреса `/concept*.html` перенаправляются на публичные страницы.

В футере находятся ссылки на `/legal/privacy`, `/legal/terms`, `/legal/offer`,
`/legal/cookies`, `/legal/consent`, `/legal/details`. Сейчас это явно обозначенные
страницы-заглушки, без действующих юридических текстов и вымышленных реквизитов.
Переключатель анимации убран из футера; системный `prefers-reduced-motion` сохраняется.

Браузеру выдаётся только production-сборка из `dist`: JS, CSS, шрифты и
используемые ресурсы. TypeScript/TSX компилируется перед запуском сервера;
исходники, sourcemaps, зависимости, служебные файлы и конфигурация недоступны
по HTTP. Сервер разрешает только публичные документы, `/app/…`, ресурсы
`/assets/…` и прокси API. Сборка не требует выдачи `.tsx` браузеру; интерактивный
интерфейс и WebGL выполняются в браузере как скомпилированный JavaScript.

## Проверка и сборка

```powershell
npm.cmd run build
npm.cmd run test:server
node --test scripts/publish-build.test.mjs
git diff --check
```

`npm.cmd run build` сначала проверяет TypeScript приложения и конфигурации Vite, затем выполняет production-сборку
Vite во временный каталог `.build-*`. После успешной сборки публикуются ресурсы,
затем HTML; каждый файл заменяется через переименование временного файла.
Прежние ресурсы с хешем в имени сохраняются для уже открытых вкладок. При ошибке
компиляции текущая версия в `dist` продолжает обслуживаться. Репозиторный
pre-commit hook запускает сборку и блокирует коммит при
ошибке. Предупреждение Vite о размере chunk не является ошибкой компиляции, но
остаётся задачей производительности.

Переходы внутри лендинга используют якоря; дополнительные страницы открываются по отдельным адресам.

Рабочие страницы загружаются отдельными JS-чанками при первом открытии.
Код помощника входит в авторизованную оболочку; само окно монтируется при первом
открытии после проверки доступа. При переходах оболочка остаётся на экране;
ошибка загрузки раздела показывает сообщение с кнопкой обновления страницы.

Плееры получают запись через авторизованный `/api/v1/calls/{uuid}/media`
с `Range` и `preload="metadata"`. Они не скачивают полный Blob и не декодируют
весь звонок для звуковой дорожки: `/media/waveform` возвращает 240 амплитуд.
Кнопки скачивания аудио и видео вызывают `POST /media/download` с новой
медиасессией и проверкой доступа на бэкенде. Произвольные прямые URL из карточки
звонка не используются. У записи, доступной для воспроизведения, нельзя
технически запретить сохранение через инструменты браузера; `nodownload`
скрывает элемент штатного интерфейса и не заменяет серверную авторизацию.

## Основные каталоги

Стили интерфейса подключаются через классы: статические правила находятся в
`src/styles`, а размеры, координаты, цвета спикеров и прогресс используют
`cssClass` и `cssStyle` из `src/shared/lib/css-styles.ts`. Последняя функция
меняет правило класса в CSSOM, а не атрибут элемента. Не добавляйте JSX
`style` и записи в `element.style`: сторонние стили холста также переводятся
в классы при запуске приложения. Повторные записи уже установленного значения
пропускаются с учётом нормализации браузером (`0` → `0px`, округление размеров),
чтобы неподвижные элементы не пересчитывали стили каждый кадр. Проверка числовых
единиц, SVG, приоритета, iframe, повторных записей и очистки неиспользуемых правил:
`node tools/verify-css-classes.cjs`
(путь к Playwright можно задать через `PLAYWRIGHT_MODULE`).

```text
src/api.ts                 HTTP-клиент и типизированные API-вызовы
src/features/              Продуктовые экраны и сценарии
src/shared/ui/             Общие элементы управления и scrollbar
src/styles/                Общие темы, layout и component styles
src/types.ts               Контракты frontend/backend
src/features/landing/      Публичный лендинг, интерактивные объекты и 3D-иллюстрации
tools/landing/             Локальная проверка отдельных иллюстраций
scripts/                   Сборка, публикация, HTTP-сервер и регрессионные проверки
```
