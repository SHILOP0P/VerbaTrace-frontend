# VerbaTrace Frontend

React/TypeScript-интерфейс VerbaTrace. Приложение работает поверх backend API из
соседнего репозитория `C:\projects\VerbaTrace` и покрывает звонки, транскрипцию и
анализ, инструкции и их версии, Human QA, действия, компании/отделы, тарифы и
credits, developer integrations, администрирование и профиль.

## Стек

- React 19
- TypeScript 5.9
- Vite 7
- MobX
- Lucide React
- PDF.js, Mammoth и ExcelJS для просмотра документов инструкций

## Локальный запуск

Backend должен отвечать на `http://localhost:8080`. Vite проксирует туда `/api`
и `/health`.

```powershell
Set-Location C:\projects\VerbaTrace-frontend
npm.cmd ci
npm.cmd run dev
```

Интерфейс будет доступен на `http://127.0.0.1:5173`. Для другого API задайте
`VITE_API_BASE_URL` без завершающего `/`.

## Bitrix24

Экран управления connection включает server-side OAuth, проверку capabilities,
pause/resume/reconnect, сопоставление пользователей и отделов, preview и запуск
backfill, историю импортов и аудит. Руководитель компании может быть сопоставлен
без отдела; для остальных сотрудников нужен активный отдел.

Диапазон backfill сохраняется в `localStorage` отдельно для UUID подключения.
Состояние `degraded` отображает доступные и недоступные возможности независимо:
например, импорт звонков остаётся доступным при подтверждённом чтении статистики,
даже если OAuth-пользователь пока не может создавать задачи.

Действие отправляется в Bitrix24 только через отдельный preview/request и решение
другого manager/department leader. Неоднозначный ответ и внешние изменения задачи
показываются как состояние, требующее ручного решения.

`Проверено на портале` нельзя считать успешным только по OAuth и read-only health
check. Нужна отдельная приёмка настоящего звонка, доступной записи, импорта и
task-flow. Аренда номера и телефонный трафик Bitrix24 могут быть платными.

## Темы и layout

Основные рабочие экраны используют общие app tokens и полностью поддерживают
светлую и тёмную темы. Для длинных панелей используется общий
`CustomScrollbar`; page layouts сохраняют одинаковые отступы относительно header
и sidebar. При добавлении элементов нельзя вводить отдельную визуальную модель,
если в проекте уже есть эквивалентный control.

Основа оформления — `src/styles/refresh.css`, он подключается последним. Шкала
поверхностей одна на обе темы: холст `--vt-canvas` → панель `--vt-s1` →
вложенный блок `--vt-s2` (заливка без второй рамки) → подсказка `--vt-s3`;
текст `--vt-text`/`-2`/`-3`, линии `--vt-line`, тона `--vt-good`/`-warn`/`-bad`/`-info`
и их `-soft`, длительности `--vt-dur-fast`/`--vt-dur`/`--vt-dur-slow`. Старые
`--app-*` указывают на эту шкалу. Оранжевый акцент — только действия, активная
навигация и фокус; данные показываются нейтральным цветом и тонами статуса.
Шрифт Inter подключён из пакета `@fontsource-variable/inter`, без внешнего CDN.
Оценка 0–100 везде показывается одним компонентом `ScoreGauge`, текст анализа
перед показом проходит через `stripAnalysisRefs`: служебные номера карточек,
требований и сегментов пользователю не показываются.
У метрики свой цвет серии (`--vt-chart-blue`/`-violet`/`-green`/`-teal`), общий
для её иконки и линии графика. Иконка, называющая страницу или блок, стоит на
нейтральной плитке `.page-emblem`; сегментированные переключатели (`.segmented`)
и фильтр спикеров — с нейтральным ползунком, без оранжевого. Тона в светлой теме
подобраны так, чтобы текст держал 4.5:1 на своей мягкой подложке.

## 3D-лэндинг

Первый экран лэндинга — офис в 3D (`src/features/landing/scene/`). Один шаг
скролла = один перелёт камеры: общий план, рабочее место сотрудника, кабинет
руководителя отдела, место заместителя, кабинет владельца. Шаг сохраняется в
`sessionStorage`, перезагрузка возвращает посетителя туда же.

На мониторах идёт настоящий интерфейс: отдельный документ `demo.html` с
`?role=employee|leader|deputy|owner`, который монтирует продуктовые компоненты на
фикстурах (`src/demo/fixtures/`) и проигрывает сценарий с нарисованным курсором
(`src/demo/scenarios/`). Страница лежит над canvas обычным 2D-слоем и попадает на
стекло, только пока камера смотрит по нормали к экрану; всё остальное время на
стекле — снимок того же экрана в стартовой позиции.

Тема мониторов — общая с лэндингом. Документ экрана того же origin, поэтому
атрибут темы ставится ему напрямую, и круговая волна переключения идёт по всей
странице, включая монитор; сценарий при этом не перезапускается.

Модели строит headless Blender 5.1:

```powershell
blender --background --python tools/office-scene/build_office.py -- --out public/assets/scene --export
blender --background --python tools/office-scene/build_figure.py -- --export
pwsh tools/office-scene/capture_screens.ps1
```

`capture_screens.ps1` снимает восемь стартовых кадров (четыре роли × две темы) в
`public/assets/scene/screens/` и требует запущенный dev-сервер. Его нужно
перезапускать после редизайна интерфейса, иначе картинка на стекле отстанет от
живой страницы.

В кабинетах руководителя отдела, заместителя и владельца сидят они сами — за
правым монитором своего стола. Камера летит к левому монитору того же стола:
она паркуется в ладони от стекла, то есть ровно там, где была бы голова, и
свободный экран — единственный способ не проходить сквозь человека и не гасить
его. Маршруты строятся по дверям кабинетов, точки маршрута выталкиваются из
сидящих (`setOccupants` / `keepOffPeople` в `scene/shots.ts`).

Место посетителя в офисе живёт в `sessionStorage` с отметкой времени и
протухает через пять минут: обновление страницы возвращает на ту же сцену, а
визит, начатый позже, открывается с общего плана.

Запасные пути: `?flat=1` — плоский первый экран без 3D, `?screens=0` — комната
без страниц на мониторах. Если WebGL недоступен или canvas упал, лэндинг сам
показывает плоский первый экран.

## Плоский лэндинг

Ниже офиса идёт `LandingStory` (`src/features/landing/LandingStory.tsx`,
стили — `src/styles/landing-story.css`): одиннадцать глав в том порядке, в
котором звонок проходит через продукт, и слева закреплённая аудиодорожка,
которая заполняется по мере прокрутки и служит навигацией по главам. Главы
описывают результат, а не механику: как именно получается разбор, на странице
не объясняется.

У каждой главы своя витрина — `src/features/landing/LandingExhibits.tsx`,
стили в `src/styles/landing-exhibits.css`. Это не картинки, а работающие куски
интерфейса на тех же токенах и тех же компонентах, что и рабочее пространство
(`ScoreGauge`, `.status-chip`, `.segmented`, `.integration-icon`,
`speakerColor`). С половиной из них посетитель может повзаимодействовать:
потянуть звуковую дорожку и увидеть, как подсвечивается реплика, выбрать
критерий и прочитать цитату-основание, включить и выключить критерий в
оценочной карте, превратить цитату в действие, переключить период аналитики,
скрыть персональные данные. Витрина появляется по мере прокрутки — это делает
сам `LandingStory` в своём обработчике, а не общий `useRevealOnScroll`: тот
молча пропускал три главы из одиннадцати.

Текст глав — единственный источник «что продукт умеет» на лэндинге. Появилась
возможность — глава пополняется; возможность ещё в разработке — на страницу она
не попадает.

## Проверка и сборка

```powershell
npm.cmd run build
git diff --check
```

`npm.cmd run build` сначала выполняет `tsc --noEmit`, затем production-сборку
Vite. Репозиторный pre-commit hook запускает эту проверку и блокирует коммит при
ошибке. Предупреждение Vite о размере chunk не является ошибкой компиляции, но
остаётся задачей производительности.
