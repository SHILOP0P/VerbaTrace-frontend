# VerbaTrace Frontend

React/TypeScript-интерфейс VerbaTrace. Приложение работает поверх backend API из
соседнего репозитория `C:\projects\VerbaTrace` и покрывает звонки, транскрипцию и
анализ, инструкции и их версии, Human QA, действия, компании/отделы, тарифы и
credits, developer integrations, администрирование и профиль.

## Стек

- React 19
- TypeScript 5.9
- Vite 7
- MobX
- Lucide React
- PDF.js, Mammoth и ExcelJS для просмотра документов инструкций

## Локальный запуск

Backend должен отвечать на `http://localhost:8080`. Vite проксирует туда `/api`
и `/health`.

```powershell
Set-Location C:\projects\VerbaTrace-frontend
npm.cmd ci
npm.cmd run dev
```

Интерфейс будет доступен на `http://127.0.0.1:5173`. Для другого API задайте
`VITE_API_BASE_URL` без завершающего `/`.

## Bitrix24

Экран управления connection включает server-side OAuth, проверку capabilities,
pause/resume/reconnect, сопоставление пользователей и отделов, preview и запуск
backfill, историю импортов и аудит. Руководитель компании может быть сопоставлен
без отдела; для остальных сотрудников нужен активный отдел.

Диапазон backfill сохраняется в `localStorage` отдельно для UUID подключения.
Состояние `degraded` отображает доступные и недоступные возможности независимо:
например, импорт звонков остаётся доступным при подтверждённом чтении статистики,
даже если OAuth-пользователь пока не может создавать задачи.

Действие отправляется в Bitrix24 только через отдельный preview/request и решение
другого manager/department leader. Неоднозначный ответ и внешние изменения задачи
показываются как состояние, требующее ручного решения.

`Проверено на портале` нельзя считать успешным только по OAuth и read-only health
check. Нужна отдельная приёмка настоящего звонка, доступной записи, импорта и
task-flow. Аренда номера и телефонный трафик Bitrix24 могут быть платными.

## Темы и layout

Основные рабочие экраны используют общие app tokens и полностью поддерживают
светлую и тёмную темы. Для длинных панелей используется общий
`CustomScrollbar`; page layouts сохраняют одинаковые отступы относительно header
и sidebar. При добавлении элементов нельзя вводить отдельную визуальную модель,
если в проекте уже есть эквивалентный control.

Основа оформления — `src/styles/refresh.css`, он подключается последним. Шкала
поверхностей одна на обе темы: холст `--vt-canvas` → панель `--vt-s1` →
вложенный блок `--vt-s2` (заливка без второй рамки) → подсказка `--vt-s3`;
текст `--vt-text`/`-2`/`-3`, линии `--vt-line`, тона `--vt-good`/`-warn`/`-bad`/`-info`
и их `-soft`, длительности `--vt-dur-fast`/`--vt-dur`/`--vt-dur-slow`. Старые
`--app-*` указывают на эту шкалу. Оранжевый акцент — только действия, активная
навигация и фокус; данные показываются нейтральным цветом и тонами статуса.
Шрифт Inter подключён из пакета `@fontsource-variable/inter`, без внешнего CDN.
Оценка 0–100 везде показывается одним компонентом `ScoreGauge`, текст анализа
перед показом проходит через `stripAnalysisRefs`: служебные номера карточек,
требований и сегментов пользователю не показываются.

## Проверка и сборка

```powershell
npm.cmd run build
git diff --check
```

`npm.cmd run build` сначала выполняет `tsc --noEmit`, затем production-сборку
Vite. Репозиторный pre-commit hook запускает эту проверку и блокирует коммит при
ошибке. Предупреждение Vite о размере chunk не является ошибкой компиляции, но
остаётся задачей производительности.
